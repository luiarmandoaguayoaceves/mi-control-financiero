Quiero que desarrolles una aplicación móvil para Android de finanzas personales usando el CAMINO WEB: **HTML5 + Tailwind CSS + JavaScript (vanilla, SIN framework)**.

IMPORTANTE:
- Mi máquina tiene Node.js v24.11.0, pero la app NO debe requerir backend: al final debe ser una carpeta de archivos estáticos (HTML + CSS compilado + JS) que se sube a Netlify.
- NO quiero React, React Native, Vue, Angular ni TypeScript en esta fase. JavaScript puro con ES Modules.
- No quiero backend ni servidores propios. La app se publica en Netlify (hosting estático).
- Los datos se almacenan como JSON en el navegador (`localStorage`): única forma de persistir en un sitio estático. Los despliegues a Netlify NUNCA tocan esos datos. Para moverlos entre dispositivos: Configuración → Exportar/Importar respaldo JSON.
- La app debe quedar diseñada para migrar después a IndexedDB/Cloud sin rehacer las pantallas: capa `store.js` (repositorio) que aísle el acceso a datos.
- Idioma de toda la interfaz: español. Moneda principal: MXN. Fechas locales de México (es-MX).
- Diseño: limpio, moderno, sobrio, estilo dashboard financiero. Modo oscuro compatible con el sistema (clase `.dark` en `<html>`, preferencia guardada en localStorage, default = seguir al sistema).
- Tailwind CSS COMPILADO en `css/tailwind.css` (sin CDN: funciona offline y en Netlify sin pasos extra).
- Estructura pensada para publicarse estática en Netlify (sin build): `netlify.toml` con `publish = "."`.

NOMBRE PROVISIONAL:
"Mi Control Financiero"

OBJETIVO:
Crear una aplicación personal para administrar mis finanzas reales día a día, reemplazando gradualmente mi Excel. Debe ayudarme a saber:
1. cuánto dinero tengo,
2. cuánto de ese dinero ya está comprometido,
3. cuánto puedo gastar realmente,
4. cuánto debo en tarjetas,
5. cuánto tengo en apartados,
6. cuánto gasto en renta, agua, luz, gas, internet, teléfono, comida, transporte, suscripciones, moto, hogar y diversión,
7. cuánto ahorro,
8. cuánto crece o disminuye mi patrimonio,
9. cómo voy respecto a mis metas financieras.

PRINCIPIO CENTRAL DE LA APP:
"Saldo bancario NO es igual a dinero libre".

La app debe calcular:
dinero libre real =
saldo disponible
- dinero comprometido para TDC
- gastos esenciales pendientes
- provisiones próximas
- metas/apartados protegidos que no deben tocarse.

REGLAS FINANCIERAS A IMPLEMENTAR (mismas que en el diseño original)
1. Compra con TDC: cada peso gastado queda respaldado por un peso de efectivo (ej: compro 600 con tarjeta teniendo 1000 libres → mi dinero libre baja a 400 aunque la cuenta muestre 1000).
2. "Monto a respaldar TDC" = compras del ciclo actual no cubiertas por un pago/apartado.
3. MSI: NO exigir todo el monto original en efectivo; mostrar mensualidad total, número de MSI, saldo pendiente y % del ingreso mensual comprometido.
4. Advertencia si las mensualidades reducen demasiado el margen mensual.
5. Fondo de emergencia: no cuenta como dinero libre, meta configurable, cobertura en meses = fondo / gastos esenciales mensuales.
6. Provisiones: gastos previsibles (seguro moto, servicio moto, mantenimiento, renovaciones) con cálculo automático de cuánto separar por mes.
7. Gasto libre calculado después de obligaciones, necesidades, provisiones, respaldo TDC y ahorro/meta definida.
8. Separar conceptualmente: gasto, ahorro, provisión, inversión, transferencia y pago de deuda.
9. Distinguir "ahorro para consumo futuro" (vacaciones) de "construcción de patrimonio" (inversión).
